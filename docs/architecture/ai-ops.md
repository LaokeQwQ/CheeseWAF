# AI Ops 设计说明

AI Ops 为控制台提供模型发现、服务商状态和本地用量统计。它只保存调用时间、服务商、调用模型和 Token 数量，不保存提示词、响应、密钥或服务商返回的原始错误正文。

## 配置模型

助手模型和推理模型使用相同的配置结构，但可以分别设置。`model` 保留旧配置兼容性；运行时优先使用 `invocation_model_name`。`display_model_name` 只用于界面展示。

| 配置项 | 用途 |
| --- | --- |
| `invocation_model_name` | 发送给服务商的实际模型名 |
| `display_model_name` | 控制台展示的模型名 |
| `context_window` | 模型上下文窗口，最大值为 2,000,000 |
| `reasoning_effort` | 推理强度，可选值为 `none`、`low`、`medium`、`high` 和 `xhigh` |
| `model_list_path` | 模型列表接口路径 |
| `balance_path` | 余额接口路径；留空时不查询余额 |
| `usage_path` | 服务商用量接口路径；留空时不查询服务商用量 |
| `configured_catalog` | 运维人员提供的模型目录，适用于没有发现接口的服务商 |

服务商路径必须位于 `api_base` 下。配置不接受完整 URL、主机名、片段、反斜线或 `..` 路径段。客户端不跟随 HTTP 重定向，因此密钥和请求正文不会被转发到另一个地址。

## 模型发现

OpenAI 兼容服务可以返回数组，也可以使用 `data`、`models`、`items` 或 `result` 包装模型数组。解析器最多展开 4 层，并且最多返回 2,000 个模型。

Anthropic 模型发现必须满足以下任一条件：

- 配置了 `model_list_path`；
- 配置了 `configured_catalog`。

两个条件都不满足时，接口返回“不支持发现”的状态。程序不会补写或猜测 Anthropic 模型名。

模型结果包含实际模型名、展示模型名、上下文窗口和支持的推理强度。程序会过滤未知的推理强度，并限制上下文窗口的最大值。

## 用量统计

每次真实的助手或推理服务商调用生成一条用量记录。记录包含输入 Token、输出 Token、总 Token、服务商和实际调用模型。

流式调用只记录一次。流式请求在收到事件前失败并改用非流式请求时，两次网络调用会分别记录。服务商调用失败时仍记录调用次数，Token 数量为 0。

内存存储默认保留最近 10,000 条记录。写入、读取和淘汰操作使用互斥锁，可在并发请求下使用。统计接口只返回汇总结果，不返回原始记录。

## 管理接口

以下接口位于管理 API 下，并要求 `read:ai` 权限：

- `GET /api/ai/ops/providers`：返回助手和推理服务商的配置状态、余额和服务商用量。
- `GET /api/ai/ops/usage`：返回本地调用次数和 Token 汇总。

用量接口支持 `1d`、`7d`、`30d` 和 `90d`。自定义查询使用 `range=custom`，并提供 RFC 3339 格式的 UTC `start` 和 `end`。开始时间不能晚于结束时间，范围不能超过 90 天，时间也不能明显超出当前时间。

## 错误和敏感数据

服务商调用错误会转换为固定的安全提示。管理接口不会返回以下内容：

- API 密钥和余额查询凭据；
- 提示词和模型响应；
- 数据库连接字符串；
- 服务商返回的原始错误正文。

AI 工具的审批规则没有变化。高风险或破坏性工具仍需要原有审批流程；审批服务不可用时，操作会被拒绝。
