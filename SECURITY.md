# Security Policy

## Reporting a vulnerability

Please do not open a public issue for an unpatched vulnerability. Contact the
repository owner privately through the GitHub security advisory workflow or
the private contact listed on the maintainer profile. Include the affected
version, a minimal reproduction, impact, and a proposed mitigation when
available. Remove credentials and personal data from all reports.

If private reporting is unavailable, open an issue containing only the words
“security contact needed”; do not include technical details or exploit code.

## Supported versions

The latest `master` release and the current `dev` branch receive security
fixes. Older releases are best-effort only; upgrade before reporting a
reproduction when possible.

## Response

Maintainers will acknowledge a report when they can, reproduce it in an
isolated environment, and coordinate a fix, disclosure timeline, and credit
with the reporter. Do not test against systems you do not own or have
permission to assess.
